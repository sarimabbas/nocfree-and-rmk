# Companion update preparation checkpoint

This checkpoint implements host-side foundations for one existing-RMK left update. It does not enable installation, restore factory firmware, modify a keyboard, or establish device eligibility.

`desktop/src/update_image.rs` accepts an exact UF2/BIN pair under the reclaimed-left policy in `scripts/migration_guard.py`. A caller receives an opaque byte-validation result only after block numbering, family, address coverage, exact BIN/page padding, vectors, recovery marker and old S140 magic checks pass. The result contains hashes and spans, not transfer permission. The Python guard remains the canonical reference; synthetic differential tests compare acceptance and every returned image field. The library itself needs no Python runtime.

`desktop/src/update.rs` binds that validated candidate to an expected reviewed hash, session, observation digest and saved-copy digest. A digest is correlation, not evidence that a recovery route or device role was verified. The journal lives in private Companion host storage. It records preparation, waiting for approval and transfer intent as separate durable events. Restarting after transfer intent requires reconciliation; there is no replay, resume or second-transfer operation. Conflicting, partial or inconsistent history stops progression. There is no device-copy backend, and no public transition can report successful installed-byte verification.

The integration test rejects mismatched candidate hashes, invalid session names, incomplete observation digests and missing saved-copy bytes. Journal tests cover scoped intent, interruption/restart, conflicting histories, partial files and host-path rejection. All fixtures are synthetic and temporary. These tests are software evidence, not hardware acceptance.

Next, connect this foundation to a trusted release manifest and fresh observations from the supported existing-left route. Preserve the current app's backup and recovery correlation, and recheck them at final confirmation. Only then add a separately reviewed one-shot transfer/readback adapter and run an owner-approved device trial. Factory migration, restoration, full-right updates and receiver recovery remain separate routes with their existing blockers.

Verification: 44 Rust tests (10 library, 33 existing app, one differential corpus test), strict all-target Clippy and formatting passed on Rust 1.98.1. The 10 canonical Python migration/restore guard tests also passed. An independent review checked guard parity, opaque binding construction, bounded journal reads, private storage paths and durable interruption handling. No keyboard was accessed or changed by this checkpoint.
