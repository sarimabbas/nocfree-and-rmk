# Lower-layout startup: independent source review

Reviewed 2026-10-01. This is a diagnosis note, not a firmware fix or permission for another device write. The first lower-layout probe's startup remains unexplained. Preserve the independently working recovery route and factory restore; do not repeat the same candidate as though its source compatibility were hardware proof.

## Observations supplied by the controlled trial

The root's local trial evidence records exact candidate readback at `0x1000`, recovery marker at `0x1200`, absent old SoftDevice magic, and two successful independent WIRED/USB-first bootloader entries. One battery-first attempt produced neither the probe USB device/greeting nor mounted bootloader. The full saved factory image was restored, with exact original readable-container SHA-256 matching afterward. This review did not operate the device.

These observations establish writable lower application flash and recoverability for this trial. They do **not** establish that the bootloader reached the application's reset handler, that clocks started, or that USB initialization ran. No USB device is an external symptom shared by several failure stages. A single failed startup also does not establish a deterministic fault.

Private evidence: `.evidence/left-migration/battery-first-startup.json`, `physical-wired-recovery-result.json`, `failed-startup-wired-recovery-result.json`, and `factory-restored-result.json`. Do not publish factory images, device identifiers, or recovery executables.

## Bootloader handoff prerequisites

The reported bootloader hash identifies upstream base `0147d71e73b9a2c217f56dbc9877d07bb45d6467`; it does not identify uncommitted NocFree changes.

- [dfu_types.h](https://github.com/adafruit/Adafruit_nRF52_Bootloader/blob/0147d71e73b9a2c217f56dbc9877d07bb45d6467/lib/sdk11/components/libraries/bootloader_dfu/dfu_types.h): SoftDevice magic selects the dynamic application base. Without it, the base is `MBR_SIZE`, `0x1000`. Exact readback of the vector and absent magic is necessary but does not observe execution.
- [main.c](https://github.com/adafruit/Adafruit_nRF52_Bootloader/blob/0147d71e73b9a2c217f56dbc9877d07bb45d6467/src/main.c): after DFU, normal startup tears down the board, checks application validity, and conditionally initializes/disables S140 **only when S140 is detected**. The recovery-first marker uses base plus `0x200`; retained-RAM and GPREGRET entries can change the startup path. Thus the no-S140 path has a different handoff, even with the same application source.
- [bootloader.c](https://github.com/adafruit/Adafruit_nRF52_Bootloader/blob/0147d71e73b9a2c217f56dbc9877d07bb45d6467/lib/sdk11/components/libraries/bootloader_dfu/bootloader.c): application startup disables/clears NVIC IRQ banks. With S140 it requests SoftDevice vector forwarding; without it it requests MBR IRQ forwarding to `0x1000`. A failed forwarding call falls back to writing `0x1000` into SRAM's first word. Retaining the application RAM floor at `0x20008000` keeps that word and bootloader retained-RAM marker outside ordinary application data.
- [Nordic nrf_mbr.h](https://github.com/adafruit/Adafruit_nRF52_Bootloader/blob/0147d71e73b9a2c217f56dbc9877d07bb45d6467/lib/softdevice/mbr/headers/nrf_mbr.h): IRQ forwarding changes runtime interrupt forwarding without reset or changing the next reset's entry. It is distinct from the persistent vector-base command; that latter command is not an appropriate diagnostic workaround.
- [bootloader_util.c](https://github.com/adafruit/Adafruit_nRF52_Bootloader/blob/0147d71e73b9a2c217f56dbc9877d07bb45d6467/lib/sdk11/components/libraries/bootloader_dfu/bootloader_util.c): the GCC handoff loads MSP and Reset from the application vector and branches, with special handler-mode exit logic. It does not explicitly clear PRIMASK/BASEPRI or reset CONTROL. The application inherits CPU/peripheral state rather than receiving a fresh hardware reset at its Reset handler.

## Application prerequisites already present

[cortex-m-rt 0.7.7 Reset](https://github.com/rust-embedded/cortex-m/blob/f259e379457008329659c3b1207f61316c35b6f0/cortex-m-rt/src/lib.rs) writes `__vector_table` to VTOR before pre-init when `set-vtor` is enabled, then initializes data/BSS and the FPU. The repository enables that feature. A missing application VTOR setup is therefore not supported by source inspection. Root also inspected this exact candidate ELF with Arm objdump: Reset at `0x1204` writes `0x1000` to VTOR (`0xe000ed08`) before DefaultPreInit, initializes BSS/data, enables the FPU, and calls main. This verifies generated instructions, not their execution on the board. The runtime does not generally normalize PRIMASK/BASEPRI/CONTROL on this path.

[nrf-mpsl 0.4.0 critical-section implementation](https://github.com/alexmoon/nrf-sdc/blob/e44e619d15eba9145453e3b2d7b07121556871ab/nrf-mpsl/src/critical_section_impl.rs) implements critical sections directly with CPU/NVIC operations. It temporarily uses PRIMASK, preserves the incoming mask, and reserves RADIO/RTC0/TIMER0 IRQs. It makes no MPSL initialization/API call. Linking it for a USB-only probe does not by itself require starting MPSL. If PRIMASK was already set at handoff, this implementation preserves it; changing critical-section providers is not yet a source-backed fix.

[Embassy nRF 0.11.0 initialization](https://github.com/embassy-rs/embassy/blob/3861d3088da30d40c777dc05d282352e68ec5511/embassy-nrf/src/lib.rs) waits synchronously for HFXO and LFCLK started events before initializing the time driver. The probe explicitly selects external HFXO and uses the default internal-RC LFCLK. These waits precede USB creation and cannot be diagnosed from missing enumeration alone. Upstream [board teardown](https://github.com/adafruit/Adafruit_nRF52_Bootloader/blob/0147d71e73b9a2c217f56dbc9877d07bb45d6467/src/boards/boards.c) stops RTC1 and LFCLK, resets GPIO, and allows a vendor-specific teardown hook. Do not assume the vendor hook is empty or that all clock/power state equals cold reset.

[HardwareVbusDetect](https://github.com/embassy-rs/embassy/blob/3861d3088da30d40c777dc05d282352e68ec5511/embassy-nrf/src/usb/vbus_detect.rs) uses POWER status and CLOCK_POWER IRQs. It reads present VBUS/power-ready state as well as waiting for event-driven wakeups. The implementation is unsuitable with an active legacy SoftDevice because POWER is reserved. That does not apply merely because S140 bytes remain elsewhere in flash; actual initialization/ownership matters. This probe starts no MPSL radio tasks.

## Plausible distinctions, not conclusions

The source does **not** prove an inherited interrupt-mask defect. Tracing the normal no-S140 path through `main.c`, `board_teardown`, `bootloader_app_start` and its GCC branch found no explicit global `__disable_irq` or BASEPRI write left across application entry. NVIC ICER writes disable individual IRQs; they are not PRIMASK. The MBR forwarding wrapper executes SVC, but the supplied header does not expose the MBR implementation's CPU-state effects. [SDK critical-region helpers](https://github.com/adafruit/Adafruit_nRF52_Bootloader/blob/0147d71e73b9a2c217f56dbc9877d07bb45d6467/lib/sdk/components/libraries/util/app_util_platform.c) enter/exit paired regions, and [nrf_nvic.h](https://github.com/adafruit/Adafruit_nRF52_Bootloader/blob/0147d71e73b9a2c217f56dbc9877d07bb45d6467/lib/softdevice/s140_nrf52_7.3.0/s140_nrf52_7.3.0_API/include/nrf_nvic.h) preserves the incoming PRIMASK around its NVIC work. This supports measuring inherited masks, not declaring them the cause. Vendor hooks, library/binary internals, and fault paths remain outside this source trace.

1. **Application never reached:** vendor application validity, no-S140 MBR handoff, or reset sequencing. Working USB-first recovery does not distinguish these from later failure.
2. **Inherited interrupt masks/mode:** no-S140 startup omits the S140 initialization/disable path. The handoff/runtime do not normalize all CPU state. Inspect masks before asserting they are wrong; global interrupts blocked could leave USB/time IRQ-dependent tasks inert.
3. **Clock initialization did not finish:** Embassy's blocking clock waits are early stopping points. Existing external-HFXO selection is already correct source configuration; replacing clocks blindly would add uncertainty.
4. **USB/power/wakeup stage:** correct vectors and clock setup still do not prove VBUS IRQ delivery, executor wakeups, or enumeration.

## Smallest useful next candidate

Prepare a diagnostic that provides **observable stages**, keeping the same lower image bounds, marker, RAM reservation, USB identity separation, and recovery route. Observe reset/pre-init, before/after Embassy clock initialization, and USB startup separately. Prefer a reviewed retained-RAM breadcrumb read by a later working diagnostic, or an independently verified safe board indicator; do not assume LED polarity/power gating. Capturing PRIMASK/BASEPRI/CONTROL/VTOR/reset reason before initialization would discriminate inherited state from a clock/USB stall. Keep diagnostic state away from the first SRAM word and the bootloader's retained marker.

An instrumented candidate should include an observable early-fault/timeout path that enters the existing recovery convention, rather than leaving another silent image. That is application instrumentation, not a new bootloader or persistent MBR command. It must preserve recovery and needs independent review before any hardware approval.

First inspect exact ELF vectors/Reset instructions and compare the working factory-layout USB diagnostic with this probe. Make one diagnosis-driven behavior change per candidate. Only if measurement confirms bad inherited masks should a mask-normalization experiment be proposed; only if a clock stage fails should a bounded clock experiment follow. This note makes no implementation or successful-startup claim.
